# personal-site

Terminal-style personal portfolio built with Next.js 16, React 19, and Tailwind CSS v4. A graphite workspace pairs readable case summaries and real project previews with file-tree navigation. The optional desktop terminal (press Ctrl + backtick) and arcade load on demand. There is no animation library: the terminal help fades in with CSS `@starting-style`.

The reading view, mobile section menu, and case disclosures work without JavaScript. Screenshot previews open in a full-color dialog with JavaScript or link directly to the image without it. Capture provenance and redesign verification are recorded in [docs/portfolio-redesign.md](docs/portfolio-redesign.md).

## Development

Use Node.js 24 LTS (also used in CI) and npm. No environment variables are required.

```bash
npm ci
npm run dev
```

## Scripts

- `npm run dev`: start the local dev server at `http://localhost:3000`
- `npm run build`: create the production build
- `npm run start`: serve the production build locally
- `npm run lint`: run ESLint
- `npm run test:dependencies`: check the ESLint dependency replacements (fast-glob and minimatch)
- `npm run test:ui`: build the app and run the Playwright browser and axe accessibility checks
- `npm run typecheck`: generate route types and check TypeScript without emitting files

## Verification

Pull requests and pushes run a locked dependency install, ESLint, TypeScript, a dependency audit, a production build, and Playwright browser checks in GitHub Actions. Run the same checks locally before review:

```bash
npm run lint
npm run test:dependencies
npm run typecheck
npm audit --audit-level=moderate
npx playwright install chromium
npm run test:ui
```

Install Chromium once per Playwright version. `test:ui` builds the production app, starts its own server on `127.0.0.1:3035`, and stops it afterward; keep that port free. After an existing build, use `npx playwright test` to run the suite without rebuilding.

For visual review, start the production server with `npm run start` and smoke-test desktop and mobile layouts, keyboard navigation, the terminal and games, résumé downloads, and external links. Check reduced-motion and JavaScript-disabled rendering after changing animations. The build downloads the Google Fonts used by `next/font` and requires network access; fonts are then served by the app.

Dependency security updates and the ESLint dependency overrides (fast-glob and minimatch) are documented in [docs/dependency-security.md](docs/dependency-security.md).

## Project Structure

- `app/`: App Router entry points, layout, and global CSS
- `components/`: reusable UI and terminal game components
- `sections/`: page-level content blocks
- `lib/`: typed content and terminal command helpers
- `public/`: static assets (including `Rafeed_Iqbal_Resume.pdf`, the downloadable résumé)

Publish the public-contact export of the general résumé at `public/Rafeed_Iqbal_Resume.pdf`. The editable master and tailoring knowledge base live in the private résumé workspace. `Resume/Rafeed_Iqbal_Cover_Letter.txt` contains the general letter used for the About copy.

## Content and metadata

`lib/content.ts` is the shared source for page content, terminal commands, and profile metadata. `PROFILE.siteUrl` uses the canonical `https://www.rafeed.dev` origin, matching the hosting redirect. The sitemap omits `lastModified` until a real content-update date can be supplied. Social cards and icons are generated by the metadata routes in `app/`.

The downloadable résumé is a separate PDF. When changing roles, dates, or projects, update the source résumé and replace `public/Rafeed_Iqbal_Resume.pdf` together after confirming the facts.

Security response headers are configured in `next.config.ts`. Hosting should serve HTTPS and preserve those headers. In production the Content Security Policy limits scripts, styles, images, fonts, media and connections to the site's own origin (plus the Supabase project on `/publicus`, read from `NEXT_PUBLIC_SUPABASE_URL` at build time, and the Vercel toolbar on preview deployments), and blocks frames, plugins, `<base>` and foreign form targets. It still allows inline scripts and styles: every page is prerendered, and a nonce would force dynamic rendering. Trusted Types are not enforced because the Turbopack runtime assigns `script.src` without a policy. `Cross-Origin-Opener-Policy` and `Cross-Origin-Resource-Policy` are `same-origin`, except that social images and icons allow cross-origin embedding.

## Publicus application

The `/publicus` and `/belong` pages are offline: their code is kept in `app/_publicus` and `app/_belong`, private folders that Next does not route. `/publicus` contains an experience-led application and procurement explorer. See [setup and verification](docs/publicus-setup.md) for the dedicated Supabase backend, and [research notes](docs/publicus-research.md) for company, data and design sources.
